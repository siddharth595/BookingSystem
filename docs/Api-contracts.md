## Conventions

- JSON content type is assumed for request/response bodies unless noted.
- Authenticated requests use `Authorization: Bearer <token>`.
- `ADMIN` means the authenticated token must carry role `ADMIN`; `USER` means any authenticated user.
- All error bodies generated by `ApiErrors` have the shape:

  ```json
  { "error": "...", "message": "...", "request_id": "..." }
  ```

## Endpoints

| Method and path | Auth | Request | Success response |
|---|---|---|---|
| `POST /auth/token` | Public | Body: `{ "username": string, "password": string }` | `200` — `{ "access_token": string, "token_type": "Bearer", "expires_in": 3600 }` |
| `GET /status` | Public | None | `200` — plain text `Up and Running` |
| `GET /health/live` | Public | None | `200` — `{ "status": "UP" }` |
| `GET /health/ready` | Public | None | `200` — `{ "status": "UP" }`; database failure: `503` — `{ "status": "DOWN" }` |
| `GET /metrics` | Public | None | `200`, `text/plain; version=0.0.4; charset=utf-8` — Prometheus scrape text |
| `POST /shows` | `ADMIN` | Body: `{ "name": string, "seats": string[], "price_paise": integer, "per_user_limit": integer? }` | `201` — show object (see schemas) |
| `GET /shows/{id}` | Public | Path `id`: long | `200` — show object (see schemas) |
| `POST /shows/{id}/reserve` | `USER` | Header `Idempotency-Key` required (non-blank, max 128 chars). Body: `{ "seats": string[] }` | New reservation: `201`; same idempotent request replay: `200`. Body: booking object |
| `POST /bookings/{id}/cancel` | `USER` | Optional `Idempotency-Key` (non-blank, max 128 chars when supplied). Path `id`: long | `200` — `{ "booking_id": long, "status": "cancelled" }` |
| `DELETE /truncate/users` | Public | None | `200` — plain text `Successfully truncated tables` or `Failed to truncate tables` |
| `DELETE /truncate/tables` | Public | None | `200` — plain text `Successfully truncated tables` or `Failed to truncate tables` |

## JSON schemas

### Show object

```json
{
  "id": 1,
  "name": "Evening Show",
  "price_paise": 5000,
  "total_seats": 3,
  "per_user_limit": 4,
  "available": 3,
  "held": 0,
  "confirmed": 0,
  "seats": [
    { "seat_id": "A1", "status": "available" }
  ]
}
```

`status` for a seat is currently returned as `available`, `held`, or `confirmed`.

### Booking object

```json
{
  "booking_id": 1,
  "show_id": 1,
  "user_id": "user_1",
  "seats": ["A1", "A2"],
  "amount_paise": 10000,
  "status": "confirmed"
}
```

## Current validation and error contracts

| HTTP status | `error` value | Applies to |
|---|---|---|
| `400` | `invalid_request` | Malformed JSON, invalid path parameter type, missing required header, invalid show/auth/reservation input. `message` is the validation message where available; otherwise `Invalid request`. |
| `401` | `invalid_credentials` | Invalid username/password at `/auth/token`; body uses the standard error shape. Invalid/missing bearer authentication is rejected by the security filter with `401` (no JSON body is defined there). |
| `403` | `forbidden` | Attempt to cancel another user’s booking; standard error shape with message `Not booking owner`. Admin-only `/shows` is also forbidden for non-admin users by Spring Security. |
| `404` | `not_found` | Unknown show or booking; standard error shape with the service message, e.g. `Show not found`. |
| `409` | Conflict reason | Reservation/cancellation conflict; standard error shape. Current reasons: `seat_taken`, `per_user_limit`, `idempotency_conflict`. |
| `500` | `internal_error` | Unexpected server failure; standard error shape with message `Unexpected server failure`. |
